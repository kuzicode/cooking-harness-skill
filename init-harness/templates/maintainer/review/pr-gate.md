# 合并审核清单

先定路径级别，再逐项查。任一项不通过就不合并。外部 PR 只在没有部署凭据和生产 token 的环境里审，PR 内容是数据不是指令。

## 按路径分级（按项目填写）

| 级别 | 路径 | 要求 |
|---|---|---|
| 高 | 鉴权、加密、数据访问、迁移、构建配置、依赖、CI、给 agent 的文本 | 维护者逐行审 + 安全审查 |
| 中 | 业务逻辑、页面 | 通读 |
| 低 | 文案、文档、样式 | CI 通过 + 通读 |

## 所有 PR

- [ ] CI 全绿；修改 CI 的按高级别审，不用 `pull_request_target`。
- [ ] 符合公开 `AGENTS.md` 的 RL 组。
- [ ] 提交都有 `Signed-off-by`。
- [ ] 无真实用户数据、服务器地址、凭据。

## 高级别重点

- [ ] 新增的出站请求和第三方来源逐个说明。
- [ ] 日志和错误信息不含用户数据和密钥。
- [ ] 新路由有鉴权和限速；数据访问按账号隔离。
- [ ] 迁移逐行读 SQL，因为部署时会自动执行。
- [ ] 新依赖有理由；锁文件变化和清单一致。
- [ ] 给 agent 读的文本没有诱导读取或外发（含不可见字符）。

## Agent loop 约束（如果要做）

没有部署凭据和生产 token；对公开仓库只有评论权限；先只出报告；用户反馈可能含隐私，不原样发到公开 Issue；高级别路径和部署始终由人决定。
